# Design Specifications

## Purpose

Own durable design decisions for repository features and architecture.

## Ownership

Each specification covers one bounded feature or system change.

## Local Contracts

- State scope, behavior, data flow, validation, and material constraints clearly.
- Keep candidate-specific private content out of design documents.
- Mark a specification's status accurately; implementation may diverge only through an explicit decision.

## Work Guidance

Update or supersede a spec when its design changes. Keep implementation details in code and deployment guides current.

## Verification

Check referenced files and statuses before using a spec as current guidance.
