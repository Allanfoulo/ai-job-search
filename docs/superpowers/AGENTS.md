# Design Work Artifacts

## Purpose

Own design and planning artifacts created during project work.

## Ownership

Durable design specifications belong in `specs/`; temporary brainstorm materials remain in their designated scratch locations.

## Local Contracts

- Specs document proposed or approved architecture; they do not replace implementation or canonical `.claude/` workflows.
- Keep specs focused on the design they cover and revise or supersede them when material decisions change.

## Work Guidance

When implementing a spec, update it only when the approved design changes. Do not copy generated or private candidate data into these artifacts.

## Verification

Review links and status claims against the current repository before citing a spec as current.
